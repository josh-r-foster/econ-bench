# Canonical result pipeline

Reviewed 2026-08-11

## Scope

This pipeline implements the canonical schema flow for benchmark version `1.0.0`. It covers capture, validation, aggregation, migration, and dashboard projection without model calls.

## Capture

Native result code uses the builders in `src/results/records.py`. A valid trial retains full prompt text, raw response text, parser output, validity state, transport fields, condition values, and experiment metrics. Prompt and response digests use SHA256 over UTF-8 text.

Canonical timestamps use UTC and end in `Z`. They include six fractional second digits. Naive legacy timestamps require an explicit IANA source timezone before conversion. The migration code never infers a timezone from the host machine.

Code revisions contain forty lowercase hexadecimal characters. Native collection records the checked out Git revision and whether tracked or untracked changes are present.

## Validation

`src/results/validation.py` composes the result, metadata, trial, and experiment metric schemas. It also verifies text digests, timestamp order, model and experiment membership, role agreement, unique trial identity, contiguous sequence indices, sample count identities, and full reproduction of derived metrics from raw trials.

`scripts/validate_results.py` evaluates every active experiment for every release matrix model. Each cell is reported as `PASS`, `PARTIAL`, `MISSING`, `INVALID`, or `EXCLUDED`.

Missing coverage and incomplete legacy provenance remain visible. The default command returns failure until every required cell passes. The `--allow-incomplete` option supports phase two diagnostics while still returning failure for invalid data.

## Aggregation

`src/results/aggregation.py` dispatches by the canonical experiment identifier. It contains one aggregator for each of the eleven active experiments. Every aggregator reads canonical raw trial records and produces the metric object defined in `schemas/experiment-metrics.schema.json`.

Invalid responses, provider failures, and interrupted trials remain in sample counts. Only valid trials enter substantive metric denominators. Empty denominators produce null rather than zero.

The derived result shares metadata with its raw records. Validation rejects mixed metadata and aggregation tools reject mixed experiments.

## Dashboard projection

`scripts/generate_dashboard_data.py` reads canonical raw and derived pairs. It recomputes aggregate metrics before writing any projection. A mismatch stops the build.

Generated dashboard files retain benchmark version, schema version, semantic model identifier, and run completion time. Their established filenames use the canonical model path key. Current pages can consume the projected trial and metric fields while phase five completes the website migration.

The rationality projection is generated by `src/tools/calculate_rationality_stats.py`. It validates and reaggregates canonical Independence and Time inputs before combining them.

## Commands

The following commands perform offline phase two operations.

```bash
python scripts/validate_results.py --allow-incomplete
python scripts/generate_dashboard_data.py
python src/tools/calculate_rationality_stats.py
```

No command in this pipeline calls a model provider.

## Partial records

A schema valid record can remain ineligible for release. Incomplete provenance, failed quality thresholds, missing matrix cells, or unavailable source fields produce partial or missing status. These states never become zeros or passing observations.
